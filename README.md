# 御朱印地圖

手機優先的御朱印蒐集地圖。純前端（HTML / CSS / JavaScript），沒有後端、沒有建置步驟、沒有追蹤。

## 功能

- 地圖上用圖釘標出寺社：**實心 = 已集，空心 = 想去**，圖釘上的字是「社」或「寺」。
- **從照片匯入**：讀取照片的拍攝位置與日期。同一天、150 公尺內的照片自動合併成一筆。
- **記錄現在位置**：在現場一鍵用目前位置和今天日期新增。
- 在地圖上點一下，新增「想去」的地點。
- 沒有位置的照片進「待定位」，之後手動補。
- 清單搜尋與篩選、照片、備註、日期。
- 底圖可切換：國土地理院地圖（日本境內，日文地名）／OpenStreetMap。
- **離線可用**：沒有網路也能打開 App、看紀錄；可以先把要去的地區地圖下載下來，在沒訊號的地方也看得到地圖。可加到手機主畫面當 App 用。
- 匯出、匯入備份（JSON，含照片縮圖）。
- **匯入 Google 地圖的「想去」清單**（清單頁 → 匯入 Google 地圖清單）：全部以「想去」匯入，名稱裡有「寺」「院」的歸為寺院，其他歸為神社。同一份檔案重複匯入不會重複。
- 深色模式、手機瀏覽器的安全區域、寬螢幕時詳細資料變成右側面板。

## 執行

需要用網址開啟，不能直接雙擊 `index.html`（瀏覽器會擋掉 ES module）。

```bash
python -m http.server 8000
```

然後開 <http://localhost:8000>。

### 放到手機上用

**定位功能只能在 https 或 localhost 使用**，所以要放到有 https 的地方。最簡單的是 GitHub Pages：

1. 在 GitHub 建一個新的 repository，把這個資料夾的內容 push 上去。
2. Settings → Pages → Build and deployment → Deploy from a branch → 選 `main`、`/ (root)`。
3. 等一兩分鐘，網址會是 `https://你的帳號.github.io/repo名稱/`。

放上去的只有程式。你的紀錄和照片存在各自手機的瀏覽器裡，不會進到 repository。

## 從 Google 地圖新增單一景點

在 Google 地圖對一個地點按「分享」→「拷貝」，回到 App 按 ＋ →「貼上 Google 地圖連結」。

- **完整網址**（`google.com/maps?q=…`）：裡面有地點名稱與地址，App 會用名稱搜尋位置，列出候選讓你確認（同名神社很多，所以一定要你點選）。
- **短連結**（`maps.app.goo.gl/…`，分享選單拷貝出來的就是這種）：裡面沒有名稱也沒有座標，網頁沒有辦法自己展開它（瀏覽器的跨網站限制），只能先放進「待定位」。
- 已經在清單裡、但沒有位置的項目：開啟詳細頁，按「用名稱搜尋位置」。

### 用 iOS 捷徑從分享選單直接加入（選用）

App 支援網址參數 `?add=`：開啟 `https://你的帳號.github.io/Goshuin-collection/?add=<Google 地圖網址>` 就會走上面的流程。
可以用「捷徑」App 做一個出現在分享選單的捷徑：
1. 新增捷徑，名稱例如「加入御朱印地圖」；在捷徑設定開啟「在分享表單中顯示」，接受類型勾選 URL 與文字。
2. 動作依序放：**展開 URL**（輸入＝捷徑輸入）→ **URL 編碼** → **文字**（內容是網站網址加 `?add=` 再接編碼結果）→ **開啟 URL**。
3. 在 Google 地圖按分享，就會看到這個捷徑。

注意：捷徑會在 **Safari** 開啟，iOS 上 Safari 與「加到主畫面的 App」資料是分開的，所以請固定用同一邊。
「展開 URL」展開後的網址有沒有地點名稱，我沒有實機驗證（只確認過在瀏覽器裡展開的網址有名稱與地址、沒有座標）。

## 從 Google 地圖匯入清單

Google 沒有開放讀取「已儲存清單」的官方介面，所以要先匯出檔案：

1. 到 [Google Takeout](https://takeout.google.com)，只勾選「已儲存」（Saved），下載後解壓縮，裡面每個清單是一個 CSV。
2. 把「神社」那份 CSV 傳到手機（或直接在手機上操作 Takeout），在 App 的「清單」頁按「匯入 Google 地圖清單」。

也支援 GeoJSON，以及 My Maps 圖層匯出的 KML（這兩種有座標，匯入後直接上地圖）。

**Takeout 的清單 CSV 通常沒有座標**，只有名稱、備註和連結。這種會進「待定位」，點開後有「開啟原始 Google 地圖連結」，
看到位置後再按「在地圖上點選」或「用現在位置」補上。如果連結裡剛好有座標，就會自動帶入。
我手上沒有真實的 Takeout 檔，欄位名稱是依公開說明推測並放寬比對；如果匯入後名稱是空的或沒有任何項目，請把檔案前幾行（可遮掉內容）給我看。

## 外觀、地址與定位（v0.5）

- **配色**：和紙／墨／朱／金（淺色與深色各一組）。神社用朱紅、寺院用靛藍，清單與地圖圖釘都用「毛筆字（社／寺）＋圖案（鳥居／三重塔）」雙重區分。圖案是自己畫的 SVG（`js/icons.js`），沒有授權問題。
- **種類標記**：圖案在下、毛筆字疊在上，沒有底色，地圖被遮住的面積很小。文字約為圖案高度的 2/3，放在圖案下方置中，上面留出鳥居的笠木與三重塔的第一層。鳥居的額束、三重塔的相輪是金黃色。清單與地圖圖釘共用同一套（`.kindmark`）。想去＝圖案只有輪廓，已集＝實心。
- **字體**：社、印用「青柳隷書しも」，寺用「正風毛筆字體 MasaFont」（SIL OFL 1.1，授權全文在 `fonts/OFL-MasaFont.txt`），標題用 Yuji Boku（OFL 1.1，`fonts/OFL.txt`）。每個字型都只切出用到的字（各約 1 KB）。青柳隷書的授權說明見 `fonts/AOYAGI-NOTES.txt`（散布時要附上原字型的兩份說明文件）。
- **預設底圖**：OpenStreetMap（可用「切換底圖」換成地理院地圖）。要預先下載離線地圖時需先切到地理院地圖。
- **地址**：從搜尋結果或匯入資料帶入；沒有時，詳細頁有「查詢地址」（座標反查，只到町／大字）。
- **定位更準**：Google 地點網址中的編號（`0x…:0x…`）前半段是 S2 格子編號，可以解出大約位置（`js/placeid.js`），用來排序同名候選。實測誤差從 14 公尺到 5.6 公里都有，所以只當線索，最後一個候選「推測位置」選了之後請在地圖上確認。
- **英文／異體字名稱**：搜尋會自動試多種寫法（Ryuonji Temple → Ryuon-ji、新舊字體等）。
- **重新匯入**：同一份清單再匯入會補上既有「待定位」項目缺的線索與地址，不會重複新增。

## 離線使用

離線功能需要 **https 網址**（放到 GitHub Pages 就有）。分三層：

1. **App 本身**：第一次用 https 網址打開後，程式檔會自動存進手機，之後沒網路也能打開。
   第一次安裝完成後要**關掉再開一次**，才會由離線版接手。
2. **看過的地圖**：瀏覽過的地圖圖磚會自動保留（最多 4000 張，超過會刪最舊的）。
3. **預先下載地圖**：地圖畫面左邊按「離線地圖」。先把地圖拉到你要去的地區（例如整個京都市區），
   選細緻程度，按「下載這個範圍」。一次最多 1000 張；範圍太大會自動降低最細的層級，
   或請你先放大地圖。請在有 Wi-Fi 的地方、出發前做。

只有**地理院地圖**開放預先下載；OpenStreetMap 的使用規範不鼓勵大量預先下載，所以那個底圖只會保留你看過的部分。
張數換算成 MB（每張約 15 KB）是粗估，實際依地區而不同；面板上的「本網站目前用量」才是實際值。

### 加到主畫面

- **iPhone（Safari）**：分享按鈕 → 加入主畫面。
- **Android（Chrome）**：選單 → 安裝應用程式／加到主畫面。

加到主畫面後會像一般 App 一樣全螢幕開啟。就我所知，iPhone 的 Safari 會自動清掉「約一週沒開」的網站資料，加到主畫面的 App 不受影響；
所以出國前請加到主畫面，並且**匯出一份備份**。

### 更新程式時（給修改程式碼的人）

- `sw.js` 開頭的 `VERSION` 要換一個新值，手機才會抓到新版；忘記改的話，手機會一直用舊的快取。
- 新增或刪除程式檔時，要同步修改 `sw.js` 的 `SHELL_FILES` 清單（`node --test` 會檢查清單裡的檔案都存在）。
- 在 localhost 開發時預設不啟用 service worker（避免看到舊檔）；要測試離線，網址加上 `?sw=1`。

## 資料與隱私

- 紀錄存在瀏覽器的 localStorage，照片縮圖存在 IndexedDB。**只在這支手機的這個瀏覽器裡。** 清除瀏覽資料或換手機就會消失，請定期到「清單」匯出備份。
- 存下來的照片是長邊 960 px 的重新壓縮縮圖，原始 EXIF（含 GPS）不會留下，備份檔裡也沒有。
- 地圖圖磚會向國土地理院或 OpenStreetMap 的伺服器載入，對方會看到你的 IP 和你看的地圖範圍（預先下載時也一樣）。程式本身不送任何資料到別處。
- 離線用的程式檔與圖磚存在瀏覽器的 Cache Storage，和紀錄一樣只在這支手機上；清除瀏覽資料會一併清掉。

## 已知限制

- **照片的位置常常讀不到。** 手機的檔案選擇器在上傳時常會移除位置。iPhone 在選照片的畫面可以點「選項」看看能不能附上位置；Android 多半會移除。讀不到時照片會進「待定位」。我沒有在實機上驗證各機型的行為。
- 離線時，沒有下載或看過的地方，地圖是空白的；紀錄、備註、照片縮圖不受影響。
- 預先下載需要圖磚伺服器允許跨網站讀取（CORS）；不允許的話，圖磚仍會顯示，但不會存進離線快取。我沒有在實機上確認地理院伺服器的行為，請先下載一小塊、關掉網路實測。
- 地理院對大量下載有沒有另外的規定，我沒有確認過，所以每次上限 1000 張、同時只送 4 個請求。
- HEIC 格式照片能不能讀取，取決於瀏覽器；iPhone 的 Safari 通常會在上傳時轉成 JPEG。
- 名稱搜尋用的是 OpenStreetMap Nominatim（備援：地理院地址搜尋）。我沒有確認過它們能從網頁直接呼叫，也沒有量過日本寺社名稱的命中率；搜不到時退回「在地圖上點選」。Nominatim 規定每秒最多 1 次，所以搜尋要按一次才查一次，不會在背景批次查詢。
- Google 地圖的「已儲存清單」沒有辦法用連結整份匯入（那需要自己的伺服器），只能用 Takeout 的檔案匯入。
- 沒有雲端同步，備份要手動。
- 範例資料的座標是概略值，出發前請自己確認。御朱印的授與時間、是否提供，請以寺社公告為準。

## 專案結構與閱讀順序

```
index.html          頁面骨架
css/style.css       樣式（深淺色、手機安全區域、寬螢幕）
js/geo.js           座標、日期、照片分組（純函式）
js/model.js         資料長相、篩選、合併、驗證備份（純函式）
js/samples.js       第一次開啟時的範例
js/store.js         localStorage / IndexedDB / 備份還原
js/photo.js         讀 EXIF、做縮圖
js/map.js           Leaflet 地圖與圖釘
js/gmaps.js         讀 Google 地圖匯出的 CSV／GeoJSON／KML（純函式）
js/geocode.js       解析 Google 地圖網址、名稱查座標
js/tiles.js         圖磚編號、下載範圍與張數的計算（純函式）
js/offline.js       service worker 註冊、網路狀態、離線圖磚的下載與用量
sw.js               service worker（程式與圖磚的快取）
manifest.webmanifest  加到主畫面用的名稱與圖示
icons/              App 圖示
js/main.js          把上面全部接起來（畫面與事件）
tests/              node 單元測試（geo、model、tiles、offline、sw、gmaps、geocode）
vendor/             Leaflet 1.9.4 與 exifr 7.1.3（已放進專案，不需要 npm）
```

建議閱讀順序：`geo.js` → `model.js` → `tiles.js` → `store.js` → `map.js` → `offline.js` → `main.js`。`geo`、`model`、`tiles` 是純函式，最容易讀。

### 測試

需要 Node 20 以上：

```bash
node --test
```

測試涵蓋 `geo.js`、`model.js`、`tiles.js`、`offline.js` 與 `sw.js`（用假的快取與網路）。畫面、地圖、照片縮圖沒有自動化測試，要在實際瀏覽器上點過。
